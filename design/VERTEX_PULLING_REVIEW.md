# N1X 정점 속성 풀링 설계 검수

2026-11-20 · 대상은 VERTEX_PULLING_DESIGN.md와 ASTRA_REVIEW_REQUEST.md에 적힌 Eden 1차 구현이다.

**판정은 벤치 진행 승인, 배포 기본값 전환 보류다.** import 메모리의 고정 기능 정점 읽기를 제거할 성능 근거는 있다. 현행 device-local 미러와 비교할 때는 물리 주소 경계, 셰이더 입력 ABI, GPU 쓰기 가시성, 정확히 같은 드로우의 비교가 먼저다.

## 입력 의미와 ABI

- **인덱스와 인스턴스.** 직접·간접 모두 VertexIndex에는 firstVertex 또는 IB 값에 더한 vertexOffset이 들어간다. firstIndex는 IB 원소 선택에 이미 반영된다. d>0 인스턴스의 설계식은 Vulkan VAF와 일치한다. 예를 들어 firstInstance=5, d=3이면 처음 세 인스턴스는 모두 스트림 원소 5를 읽는다. Vulkan의 instance-rate divisor=0은 firstInstance 원소 고정이다. 현재 NVN→Eden은 divisor=0을 vertex-rate로 구성한다. 두 계약을 구분하고, 게스트에 노출하는 보정된 InstanceId와 풀링에 쓰는 원시 InstanceIndex도 분리한다. [Eden 상태 구성](../source/src/video_core/nvn/nvn_pipeline_key.cpp#L453) · [Vulkan 정점 입력 주소 계산](https://docs.vulkan.org/spec/latest/chapters/fxvertex.html#fxvertex-input-extraction)
- **형식.** Eden은 vertex_format(fmt, 0, 0)을 호출하고, 키 작성 중 VkFormat을 Maxwell size/type으로 바꾼다. host 자체 번역기의 r75 정수 재해석을 Eden에 그대로 옮기면 입력이 달라질 수 있다. Eden이 최종 선택한 VkFormat과 IR의 Bitcast/SToF/UToF를 대조한다. 현행 키는 BGRA를 독립 비트로 보관하지 않는다. 추가 swizzle이 필요하면 서로 다른 입력이 같은 키가 되는지 먼저 확인한다. 10:10:10:2는 A2B10G10R10의 성분 순서와 2비트 부호·정규화, B10G11R11은 unsigned float의 5비트 지수와 각 성분의 가수 폭을 따로 검증한다. 비활성 속성, 형식에 없는 성분, 0-filled 버퍼에 실제로 있는 성분, OOB를 각각 테스트한다. [Eden 형식 입력](../host/dm/windows/gfx_vk_eden.inc#L103) · [형식 키](../source/src/video_core/nvn/nvn_pipeline_key.cpp#L437) · [최종 VkFormat](../source/src/video_core/renderer_vulkan/vk_graphics_pipeline.cpp#L850)
- **정규화 수치.** ARM64 Windows에서 단정도 fmaf로 보정식을 실행했다. 2·8·10·16비트 UNORM/SNORM 전수에서 c/D를 binary32로 반올림한 CPU 기준과 불일치는 각각 0개였다. SNORM 최솟값의 -1 포화도 포함했다. 기존 57,359개 차이는 속성들을 더한 최종 varying과 위치의 비교이므로 어느 변환이 원인인지 분리할 수 없다. membench4는 산술을 섞기 전 개별 성분의 비트를 기록하고, 정확한 0·부호 있는 0·정상/비정상 half·Inf·NaN을 구분한다. NaN payload 보존을 요구할 형식과 드라이버 관측에만 의존하는 경우도 구분한다. LUT는 남은 차이의 입력 패턴을 확인한 뒤 비용을 재측정한다.
- **robustness.** 단독 호스트의 en.robustBufferAccess=0이 NXN1X가 인계한 실제 VkDevice의 설정을 입증하지 않는다. 실제 enabled feature와 파이프라인별 override를 기준으로 기록한다. 정상 범위에 대해 동등성을 요구하고, BDA 범위 밖에서 명시적으로 반환할 값을 별도 계약으로 둔다. [기기 인계](../source/src/video_core/renderer_vulkan/nvn_bridge_device.cpp#L49)
- **푸시 상수와 수명.** Eden 그래픽 레이아웃은 이미 ALL_GRAPHICS로 정점 단계를 포함한다. 현재 그래픽 범위는 48바이트이며 8바이트 정렬 주소를 offset 48에 배치하면 56바이트다. 기존 render-area와 rescaling이 offset 0을 사용하는 조건부 레이아웃이라는 점을 보존한다. 한 엔트리 포인트에서 정적으로 사용하는 push-constant 블록 하나에 주소를 포함하고, 동일한 ALL_GRAPHICS 범위를 확장한다면 푸시할 때도 그 stage mask를 사용한다. NXN1X의 vk_scratch는 BDA 사용 비트와 메모리 할당 플래그를 이미 지원한다. 일단 명령에 쓰인 테이블 사본은 완료 펜스까지 불변이어야 한다. 같은 제출 안에서도 내용이 달라지면 새 공간을 할당하고, 값이 같아도 command buffer 분할·호환되지 않는 레이아웃 변경 뒤에는 다시 푸시한다. [레이아웃](../source/src/video_core/renderer_vulkan/pipeline_helper.h#L246) · [기존 푸시](../source/src/video_core/nvn/nvn_shader_bridge.cpp#L839) · [scratch 할당](../host/dm/windows/gfx_vk_core.c#L2707) · [Vulkan push 명령](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdPushConstants.html)
- **키와 단계.** VIDS off / EDS1 on에서 stride를 동적 테이블로 넘기는 판단은 맞다. 같은 포맷에서도 VAF와 풀링을 모두 사용하면 최대 두 변형이 생긴다. outer replay key, 마지막 파이프라인 빠른 경로, 내부 GraphicsPipelineCacheKey와 디스크 레시피가 같은 모드를 선택하도록 한다. 특히 실시간 전환 시 상태 버전이 그대로면 eden_graphics가 키를 다시 만들기 전에 이전 파이프라인을 반환할 수 있다. 현재 NVN 브리지는 VertexB부터 환경을 구성한다. 일반 Eden의 A+B 병합 결과도 Stage::VertexB이므로 stage만으로 병합 셰이더를 제외할 수 없다. support_scaled_attributes는 현재 소스의 기본 초기화와 프로필식으로는 true다. [빠른 경로](../host/dm/windows/gfx_vk_eden.inc#L218) · [NVN 단계](../source/src/video_core/nvn/nvn_shader_bridge.cpp#L529) · [병합](../source/src/shader_recompiler/frontend/maxwell/translate_program.cpp#L485) · [프로필](../source/src/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L641)
- **미러 비용.** vbm은 첫 바인딩 때 청크 전체 크기의 device-local 버퍼를 만든다. IB 하나만 남아도 같은 청크의 할당량은 유지될 수 있다. 정점 복사 바이트, 인덱스 복사 바이트, 보호 페이지·폴트, 청크 할당량을 나눠 기록하고 새 프로세스 같은 장면에서 비교한다. 간접 IB는 현재도 미러를 거치지 않으므로 첫 단계 범위로 확장할 필요가 없다. [청크 할당](../host/dm/windows/gfx_vk_exec.c#L437) · [간접 IB 분기](../host/dm/windows/gfx_vk_exec.c#L3539)

## 승인 단계

1. **독립 벤치.** 현재 미러에 대응하는 기준과 BDA + 고정 기능 IB 후보를 같은 입력으로 교차 측정한다. 단일 위치 속성 및 정렬된 float로 시작해 다중 스트림, divisor 2·3, nonzero firstInstance, stride 0, 음수 vertexOffset의 유효 결과 및 청크 끝으로 확대한다. GPU 스코프 시간과 호스트 테이블 생성 비용을 각각 기록한다.
2. **기본 끔 Eden 프로토타입.** 단일 VertexB, 직접 indexed draw, 정렬된 지원 형식, 전체 범위가 한 버퍼로 증명된 드로우만 허용한다. 미지원 드로우는 파이프라인 선택 시점에 기존 미러를 선택한다. Vulkan 1.4 대상 spirv-val, Vulkan validation 및 동기화 검증, 개별 속성 비트 비교를 통과시킨다. 분할 command buffer와 같은 제출 내 GPU write→VS read를 포함한다.
3. **게임 A/B.** 젤다무쌍2 동일 저장 지점·카메라·캐시 상태, 보간 끔에서 기존 미러와 후보의 GPU p50/p95, 원본 프레임 p50/p95, 복사량과 보호 폴트를 비교한다. 풀밭 외에도 깊이 프리패스/EQUAL 컬러 패스, 재시작 인덱스·쿼드 변환, 간접 드로우, XFB 생산→정점 소비를 포함한다. 후속 GS·테셀레이션의 varying 입력은 원래 인터페이스를 유지하고, mesh·미지원 혼합 단계는 폴백한다. 기능을 켰다 끈 후 캐시 재사용과 재시작도 확인한다.

이번 검수는 소스·기존 측정 대조 및 CPU 변환식 전수 검사까지다. 제안한 조합의 GPU 벤치, 생성될 SPIR-V, 게임 내 성능·출력은 구현 후 검증 대상이다.
