# NXN1X release 2026-11-22 — technical notes

Build: `build\release\bin\NXN1X.exe` 12:50:38 (the 12:49 release candidate with comment corrections only).
Originals of every changed file: `_backup\fefs\`, `_backup\xcde_dlssrange\`, `_backup\icons_prev\`, `_backup\` (NCE cleanup).

Most changes have one switch (environment variable) that restores the old behaviour, and a log line that shows it acting. Exceptions: `maxe4k` is a constant (no switch), and the NCE crash ring is a compile-time define (`NXN1X_CRASH_RING`).

## 1. Xenoblade Chronicles DE / Xenoblade Chronicles 2 (Switch 2 Edition): black title, frozen intro — `dlssrange`

- **Symptom:** XCDE title background black, intro movie frozen (about one second of picture at each day/night branch); XC2 the same and no 3D.
- **Cause:** `nvnDlssNetworkBuilderGetOptimalSettings` was answered in NGX order (optimal, largest, smallest) with one size. NVN2 returns optimal, **smallest**, **largest**; the game stores arguments 3/4 as the lower bound and 5/6 as the upper (main+0x7742c0) and evaluates DLSS only when its input is inside that range (main+0x7745e0). The title renders 1280x720, so DLSS was skipped and the next compute pass scaled an unwritten 1920x1080 image to 4K.
- **Fix:** `host/dm/gfx/nvn/hle_nvn.c:3567` — order optimal / smallest / largest, range output/3 .. output.
- **Switch / log:** `DM_NVN_DLSS_RANGE=0`; `dlssrange:`.

## 5. Booting a dump folder (`exefs/main`)

- **Identification:** `core/loader/loader.cpp:106` — the deconstructed-directory check runs before the NSO check, so `exefs/main` boots as a dump folder.
- **`dirfs`** (`core/loader/deconstructed_rom_directory.cpp:296`): a loose `exefs/main` boot had no NCA/NSP/NUP loader to register the process with the FS controller; the game's `fsp SetCurrentProcess` got 2002-1002 (TargetNotFound) and it terminated itself (Fire Emblem: endless loading). The process is now registered with a RomFS from a `.romfs` file in `exefs/` or a `romfs/` folder beside it. `NXN1X_DIRFS=0`; log `dirfs:`.
- **`maxopen`** (`core/file_sys/vfs/vfs_real.cpp:43`): the VFS keeps up to 8192 files open through CRT `FILE*`s; the CRT allowed fewer (2048 here), so a 250k-file RomFS folder failed opens with "Too many open files" after the intro. The CRT limit is raised to 8192 and 1024 kept for everything else. `NXN1X_VFS_MAXOPEN=<n>` (sets the count by hand, CRT limit untouched); log `maxopen:`.
- **`fsfail`** (`core/hle/service/filesystem/fsp/fs_i_filesystem.cpp:22`, `fsp_srv.cpp:275`): failing guest FS calls log their path at Warning level (LOG_DEBUG is compiled out in release). First 64. `NXN1X_FS_FAIL_LOG=0`.

## 7. Fire Emblem Fortune's Weave (04007EF01F8AE000, v131072)

### 7.1 Draws skipped at 1024 descriptors — `maxe4k`
- **Symptom:** `an Eden pipeline has 1035 descriptors (more than 1024): its draws are skipped`, and `dispatch … dropped: Eden pipeline or descriptors unavailable`.
- **Cause:** `EDEN_MAXE` (the host's working array for one pipeline's set-0 entries) was 1024 — the shader recompiler's limit for **one** indexed texture array (`texture_pass.cpp:99 DESCRIPTOR_MAX_COUNT`), taken as the limit for **all** of a pipeline's descriptors. FE: one 1024-element array + 11 other bindings. `eden_ready_w` refused the pipeline; the dispatch path (`eden_dispatch_prep`) goes through the same check.
- **Fix:** `host/dm/windows/gfx_vk_eden.inc:15` `EDEN_MAXE = 4096`. Every user of the constant was checked (319 refusal, 1375/1414 fill, 1436–1439 s35 compare, 1452 set hash); the arrays are heap-allocated per recording context.

### 7.2 Light textures read through a computed index — `htarr` + `cidx`
- **Symptom:** 32 × `Bindless … handle not computable per draw (stopped at Phi / FPAdd32): taking cbuf0+0x510, a pointer: no texture`.
- **Cause (from `handletree:`):** a fragment shader loops over the set bits of a per-pixel light mask (`LoadStorage32` → `BitReverse` → `FindUMsb`, loop `Phi`) and reads each light's texture handle at `cbuf0[0x510] + light × stride` (`LoadStorage64`). Two gaps:
  1. `HostTranslateInfo::support_handle_table_arrays` was never set, so the per-invocation handle-table path was dead code.
  2. That path only took a *loaded* word as the element index; this index is computed by the shader.
- **Fix:**
  - `htarr` (`video_core/renderer_vulkan/vk_pipeline_cache.cpp:727`): on for the NVN host device when non-uniform sampled image array indexing is supported (N1X: yes). `NXN1X_HANDLE_TABLE_ARRAYS=0`; log `htarr:`.
  - `cidx` (`shader_recompiler/ir_opt/texture_pass.cpp:881`): an operand scaled by the table stride that cannot be computed per draw becomes the element index (same conditions as the existing index path: first read's address, sampled textures only, dominance checked, index clamped to `HANDLE_TABLE_SIZE` 64). `NXN1X_HANDLE_CIDX=0`; log `cidx:`.
- **Result:** `no texture` 32 → 0. The host already filled each element (`nvn_eden_eval_handle`, `HandleOp::Index`) and the SPIR-V backend marks the index `NonUniform`.
- **Reach:** every Switch 2 game; shaders that previously bound no texture now bind the table's. Regression check advised.

### 7.3 Upside-down render-target copies — `copymirror`
- **Symptom:** the character card (save slot, defeat condition) upside down since the first run.
- **Cause:** NVN copy flags `MIRROR_X` (0x4) / `MIRROR_Y` (0x8) were dropped by the Vulkan texture copy (`gfx_vk_exec.c`); the Metal backend walks a mirrored source from its far edge (`nvn_mtl.m:11596`). FE copies its 608x608 card render target into a 500x500 texture with `MIRROR_Y`.
- **Fix:** `host/dm/windows/gfx_vk_exec.c:5482` — a mirrored copy goes through `vkCmdBlitImage` with the source region's edges swapped. `NXN1X_COPY_MIRROR=0`; log `copymirror:` (4 in the confirming run). Confirmed fixed by NPARK.

### 7.4 Finalized programs leave queue bindings — `progforget` (nxnative 1440a73)
- **Cause:** NVN reads a program only when bound; a game may finalize a program a queue still has bound and reuse its memory (FE at the title → opening demo). Windows' `mtl_prog_forget` was an empty stub, so the pointer stayed in `S.prog` and in the saved per-queue states (r72) and the next `prog_key` hashed reused memory.
- **Fix:** `host/dm/windows/gfx_vk_exec.c:204` — the finalized program is cleared from the active state and every saved queue state under the submission lock (stub removed from `gfx_vk_win_glue.c`). `DM_VK_PROG_FORGET=0`; log `progforget:`.

### 7.5 Frame generation changes — `opthold`, `viewusage` (the device lost is NOT fixed)
- `opthold` (`video_core/renderer_vulkan/renderer_vulkan.cpp:573`, `nvn_display.cpp` `Generation()`): frame generation waits until the NVN output copy has kept its size and format for 8 originals (FE's first present is 10-bit, the next ones 8-bit sRGB). `NXN1X_OPT_HOLD=0`; log `opthold:`.
- `viewusage` (`video_core/renderer_vulkan/vk_present_manager.cpp:399`): with frame generation on, frame images carry STORAGE usage; their sampled/attachment view (sRGB for FE) now states its usages through `VkImageViewUsageCreateInfo` instead of inheriting STORAGE (invalid for sRGB). `NXN1X_VIEW_USAGE=0`; log `viewusage:`.

### 7.6 Checked against the other FE ports (already in our code or not applicable)
- nxnative 0a759de7: scaled shared memory addresses (`lower_to_maxwell.h:1816`, 1522), IMAD.HI pair + IMAD.X carry (915–990, 1040), NVN2 workgroup counts at c0 + 4 (`dmsh_abi.h:34`, `gfx_vk_exec.c:3096`, 5318), SDK 22 bindless TEX forms 0x361/0xf60/0x370 (`lower_to_maxwell.h:2359`, 2867), handle table base past the array (Eden's arrays start at the cbuf offset), pending clears before a dispatch (`vk_end_pass` commits a clear-only pass; `clrorder` diagnostic 0 in FE runs).
- BananaNative #135: per-element texture handles (`eden_handle` k), vertex attribute rebind replaces all (`gfx_vk_exec.c:6092`), display max resolution (FE outputs 2560x1440), DLSS (real DLSS here); Qualcomm/Turnip and dav1d items are Android only.

## 9. Known issues

1. **FE tutorial square darker than the console.** The measured scene luminance (16x16 RGBA16F) is 137.25 (log2 7.10) against nxnative's console-matched 134.4 (log2 7.07), so exposure step 1 is right; the histogram, the 64-bit average and the 3x1 exposure image were not captured (`expoprobe` saw no 3x1 read outside a pass). Next: capture the exposure image where the tonemapper samples it (inside the pass, via a copy after the pass) and compare with 5.555; then the lighting composite.
2. **FE with frame generation on at start: device lost** at tick 6 (about 3 s). With frame generation off at start it runs; F10 (runtime toggle) does not help because frame images keep STORAGE usage from the start. Frames created without STORAGE did not lose the device in one run. Not fixed by `opthold` or `viewusage` alone. Next: NV checkpoints on the compositor's queue.
3. **Regression check pending** for `htarr` / `cidx` / `copymirror` on other Switch 2 games (Mario Kart World, Donkey Kong Bananza, Xenoblade DE).
